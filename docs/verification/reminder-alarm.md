# 训练历史与 Android 闹钟式提醒

## 变更

训练历史使用 Drift 数据流实时刷新，包含实际组记录及仅标记完成的训练动作。未执行的计划不算作已训练；取消完成或删除组记录会同步更新历史。

Android 提醒由 AlarmManager 唤醒接收器，再启动前台服务。服务使用 USAGE_ALARM 播放循环铃声，或重复振动，提供锁屏关闭页和通知关闭按钮，十分钟后自动停止。自选铃声无法访问时回退系统闹钟铃声；不更改用户系统音量。仅有通知权限不能代表精确闹钟或全屏权限已授权，提醒页分别检查并提示。

原生计划保存到 SharedPreferences，每个星期槽在触发后续约；启动、应用更新、系统时间/时区变化与精确闹钟授权后恢复计划。不开启应用超过七天也能继续调度。闹钟服务被系统拒绝时退回普通通知，并留下原生日志。

## 验证

- Flutter 全套回归通过，包括训练记录增删、仅勾选完成、通知与精确/全屏权限分离检查。
- 变更文件 Dart 静态分析通过，Android 调试 APK 构建通过。
- OPPO/ColorOS 真机尚未连接，不能以模拟器或编译结果保证特定机型响铃和振动表现。

## OPPO 验收步骤

1. 安装最新构建，在“提醒”中允许通知、精确闹钟和全屏提醒；从页面中的厂商设置入口允许自启动、后台运行。
2. 响铃模式把系统“闹钟音量”调到可听见的水平，设定下一分钟；分别前台、后台、熄屏验证到点响铃，关闭后应停止。
3. 振动模式重复相同场景，确认持续振动、无铃声、关闭后停止。
4. 改用自选铃声，确认切换有效；重启后检查下一次提醒仍存在。
5. 关闭精确闹钟权限后，页面必须提示可能延迟；关闭全屏权限后保留通知关闭入口。

应用无法绕过用户强制停止、系统禁止后台运行、闹钟音量为零或免打扰策略；具体 OPPO 机型仍须实测。当前未实现系统时钟应用的稍后提醒功能，多个同时到点的提醒合并为最新一个活动闹钟。

参考：[Android 闹钟调度](https://developer.android.com/develop/background-work/services/alarms)、[Android 14 全屏提醒限制](https://source.android.com/docs/core/permissions/fsi-limits)。
